# SURE English TTS WER Optimization with F5-TTS

## Task and Metric

This task optimizes the SURE `tts_en_wer` task with F5-TTS.

- **Canonical task**: TTS
- **Language**: English
- **Primary metric**: tts_wer
- **Optimization direction**: lower is better
- **SURE route**: `tts.en.tts_wer.whisper_large_v3.whisper_norm.wenet_wer`

SURE is used only as the read-only evaluator. Candidate scripts must synthesize
audio and write a TTS samples JSONL file. EvoMaster calls SURE after artifact
generation to transcribe the audio and compute WER.

## Base Model and Workspace Paths

The task must start from the configured F5-TTS base model/source tree. In every
SURE Master experiment workspace, use workspace-relative paths:

- **F5-TTS root**: `base_model/root`
- **Evaluation prompts**: `base_model/eval_data/prompts.jsonl`
- **Fine-tuning manifests**: `base_model/train_data`

Do not use or write to the external source path directly:

```text
/hpc_stor03/sjtu_home/chaolei.liu/TTS/F5-TTS
```

The F5-TTS root contains:

- `src/f5_tts/infer/infer_cli.py` - command line inference entry point
- `src/f5_tts/api.py` - Python API wrapper
- `src/f5_tts/train/train.py` - accelerate training entry point
- `src/f5_tts/train/finetune_cli.py` - fine-tuning entry point
- `src/f5_tts/configs/F5TTS_v1_Base.yaml` - default base config
- `src/f5_tts/infer/examples/basic/basic_ref_en.wav` - default English prompt audio

## Required Output Contract

The candidate script must create:

```text
artifacts/samples.jsonl
artifacts/wavs/*.wav
```

Each `samples.jsonl` row must be a JSON object:

```json
{"sample_id":"f5_en_001","prediction_audio":"wavs/f5_en_001.wav","reference_text":"target text","reference_audio":"../base_model/root/src/f5_tts/infer/examples/basic/basic_ref_en.wav","language":"en"}
```

`prediction_audio` is resolved relative to `artifacts/samples.jsonl`, so
`wavs/f5_en_001.wav` means `artifacts/wavs/f5_en_001.wav`.
`reference_text` must be the target text that should be spoken by the generated
audio, not the prompt-audio transcript.

The fixed prompt rows are in `base_model/eval_data/prompts.jsonl` with fields:

```json
{"sample_id":"...","language":"en","reference_audio":"...","reference_text":"prompt transcript","target_text":"text to synthesize"}
```

Use all rows unless `SURE_TTS_MAX_SAMPLES` is set to a smaller positive number.

## Evaluation Data Stages

Regular F5-TTS configs use the existing SURE Master loop where each run sees
exactly one prompt set through `base_model/eval_data/prompts.jsonl`. The staged
F5-TTS config uses `search_strategy: staged_axes`: it screens architecture,
fine-tuning, and inference axes separately, then evaluates limited combinations.
This is still a bounded self-optimization loop; it is not from-scratch model
training or an unrestricted source-code search.

The staged prompt sets are generated by:

```bash
python playground/sure_master/tools/build_f5tts_eval_data.py
```

Use these configs for normal self-optimization runs:

| Stage | Rows | Config |
| --- | --- | --- |
| Smoke | 20 | `configs/sure_master/gpt-5-f5tts-smoke.yaml` |
| Early search | 200 | `configs/sure_master/gpt-5-f5tts-early-search.yaml` |
| Regular search | 800 | `configs/sure_master/gpt-5-f5tts-regular-search.yaml` |
| Selection | 500 | `configs/sure_master/gpt-5-f5tts-selection.yaml` |

For staged self-optimization, use:

```text
configs/sure_master/gpt-5-f5tts-staged-axes-mixed.yaml
```

That config uses `smoke` for the official draft, `regular_search` for axis
screening and combinations, `selection` for reranking, and `holdout` only for the
final selected candidate plus baseline check. Architecture-axis screening uses
`SURE_TTS_ARCH_INIT_MODE=scratch` so every structure candidate starts from the
same random-initialization condition. Combination, selection, and holdout use
`SURE_TTS_ARCH_INIT_MODE=partial_load` to warm-start compatible parameters from
the official F5-TTS checkpoint before bounded training. The staged config also
sets `SURE_TTS_ARCH_FORCE_INIT_MODE` so a candidate cannot accidentally override
the stage initialization policy with a contradictory CLI flag.

The generated `holdout` prompt set is reserved for a final private check after
an approach has been selected. Do not use holdout rows during search, debugging,
prompt iteration, or idea selection.

## Batch Inference Wrapper

Candidate scripts must use the controlled batch inference wrapper for F5-TTS
generation:

```bash
"$SURE_TTS_PYTHON" "$SURE_TTS_BATCH_INFER_WRAPPER" \
  --nfe-step 32 \
  --cfg-strength 2.0 \
  --sway-sampling-coef -1.0 \
  --speed 1.0 \
  --text-cleanup none
```

Do not launch `base_model/root/src/f5_tts/infer/infer_cli.py` once per prompt.
That pattern reloads Python, F5-TTS, vocoder, and checkpoint for every sample
and is too slow for regular search or selection.

The wrapper reads `base_model/eval_data/prompts.jsonl`, loads the model and
vocoder once per worker, shards prompts across the GPUs already assigned through
`CUDA_VISIBLE_DEVICES`, writes `artifacts/wavs/*.wav`, writes
`artifacts/samples.jsonl`, and records `artifacts/candidate_changes.json`.
Use wrapper flags to express inference-level actions:

| Flag | Purpose |
| --- | --- |
| `--nfe-step` | denoising steps |
| `--cfg-strength` | classifier-free guidance |
| `--sway-sampling-coef` | sway sampling coefficient |
| `--speed` | generated speech speed |
| `--remove-silence` | remove long generated silence when set to `1` |
| `--text-cleanup` | `none`, `typography`, or `conservative` |
| `--ckpt-file` | checkpoint to evaluate after fine-tuning or architecture training |
| `--model-cfg` | model config to evaluate after architecture training |

After a training or architecture wrapper succeeds, pass its checkpoint/config to
the batch wrapper instead of calling `infer_cli.py` directly.

## Training-Level Action Space

Training is allowed only as bounded fine-tuning through the controlled wrapper:

```bash
"$SURE_TTS_PYTHON" "$SURE_TTS_FINETUNE_WRAPPER" \
  --action finetune_short \
  --train-manifest libritts_train_clean_100_1h \
  --max-steps 1000 \
  --learning-rate 3e-6 \
  --effective-batch-size 8 \
  --freeze-policy none
```

The wrapper writes:

```text
models/f5tts_finetune/final_checkpoint.pt
models/f5tts_finetune/training_summary.json
models/f5tts_finetune/prepare_dataset.log
models/f5tts_finetune/finetune.log
```

After a successful fine-tune, use
`models/f5tts_finetune/final_checkpoint.pt` as `--ckpt_file` for F5-TTS
inference and continue to pass `SURE_TTS_VOCAB_FILE` as `--vocab_file`.

Allowed training actions:

| Field | Allowed values |
| --- | --- |
| `action` | `no_train`, `finetune_short` |
| `train_manifest` | `libritts_train_clean_100_1h`, `libritts_train_clean_100_5h`, `libritts_train_clean_100_10h` |
| `max_steps` | `500`, `1000`, `2000`, `5000` |
| `learning_rate` | `1e-6`, `3e-6`, `5e-6`, `1e-5` |
| `effective_batch_size` | `8`, `16`, `32` |
| `freeze_policy` | `none` |

The fine-tune manifests are generated from LibriTTS `train-clean-100` by:

```bash
python playground/sure_master/tools/build_f5tts_train_manifests.py
```

Do not call `base_model/root/src/f5_tts/train/finetune_cli.py` directly from a
candidate script. The wrapper copies F5-TTS to `working/f5tts_finetune`, patches
that local copy with a hard `max_steps` stop, writes checkpoints only under
`models/f5tts_finetune`, and kills the full subprocess group on timeout.

Plain fine-tuning candidates must keep the F5-TTS architecture fixed and start
from `SURE_TTS_BASE_CKPT_FILE` / `SURE_TTS_CKPT_FILE`.

## Architecture-Level Action Space

Architecture-level changes are allowed only through the controlled architecture
wrapper:

```bash
"$SURE_TTS_PYTHON" "$SURE_TTS_ARCH_WRAPPER" \
  --action arch_finetune_short \
  --init-mode partial_load \
  --train-manifest libritts_train_clean_100_1h \
  --max-steps 2000 \
  --learning-rate 3e-6 \
  --effective-batch-size 8 \
  --depth 20 \
  --ff-mult 2 \
  --conv-layers 4 \
  --qk-norm none \
  --attn-mask-enabled 0 \
  --checkpoint-activations 1
```

Allowed architecture actions:

| Field | Allowed values |
| --- | --- |
| `action` | `no_arch`, `arch_finetune_short` |
| `init_mode` | `scratch`, `partial_load` |
| `depth` | `18`, `20`, `22`, `24` |
| `ff_mult` | `2`, `3`, `4` |
| `conv_layers` | `2`, `4`, `6` |
| `qk_norm` | `none`, `rms_norm` |
| `attn_mask_enabled` | `0`, `1` |
| `checkpoint_activations` | `0`, `1` |

The architecture wrapper keeps `dim=1024`, `heads=16`, `text_dim=512`,
tokenizer, vocab, mel config, and vocoder fixed. In `partial_load` mode it loads
compatible weights from the base checkpoint, rejects candidates below the
configured match threshold, trains under a hard `max_steps` limit, and may stop
early when the smoothed training loss has converged. In `scratch` mode it skips
base-checkpoint loading and records this explicitly in
`models/f5tts_arch/partial_load_stats.json`.

For staged F5-TTS, use `scratch` only during architecture-axis screening. Do not
reuse scratch checkpoints as final models. After the top architectures are
selected, combination/selection/holdout should retrain the chosen structure with
`partial_load` and the selected training strategy, then use
`models/f5tts_arch/final_checkpoint.pt` as `--ckpt_file` and pass
`models/f5tts_arch/model_cfg.yaml` as `--model_cfg` to F5-TTS inference. When
`SURE_TTS_ARCH_FORCE_INIT_MODE` is set, it overrides `--init-mode` so the staged
runner can enforce this boundary.

F5-TTS may download the model checkpoint and vocoder through Hugging Face or
ModelScope if they are not cached. Prefer the mounted caches:

```text
/hpc_stor03/sjtu_home/chaolei.liu/.cache/huggingface
/hpc_stor03/sjtu_home/chaolei.liu/.cache/modelscope
```

The Docker task normally sets `HF_HUB_OFFLINE=1`, so generated scripts should
not rely on network access during inference. The F5-TTS checkpoint, vocab, and
Vocos cache are expected to be available from the mounted cache paths above.

## Expected Candidate Script Behavior

Generated `run_sure.py` should:

1. Run from the current experiment workspace.
2. Read prompts from `base_model/eval_data/prompts.jsonl`.
3. Use `base_model/root` as the only F5-TTS source path.
4. Generate real speech audio under `artifacts/wavs/`.
5. Write `artifacts/samples.jsonl` in SURE TTS format.
6. Save logs, temporary configs, and optional local model changes under
   `working/` or `models/`.
7. Exit non-zero if valid generated audio cannot be produced.
8. Write `artifacts/candidate_changes.json` describing the actual changes.
9. If plain fine-tuning is used, call only `SURE_TTS_FINETUNE_WRAPPER` and then
   infer with its `final_checkpoint.pt`.
10. If architecture training is used, call only `SURE_TTS_ARCH_WRAPPER` and then
    infer with its `final_checkpoint.pt` and `model_cfg.yaml`.

It must not:

- import or call `sure_eval`
- import `audioop`; use `wave`, `soundfile`, `numpy`, or simple file-size and
  WAV-header validation instead
- reject `base_model/root`, `base_model/eval_data`, checkpoint files, vocab
  files, or configured input roles just because their symlink-resolved target is
  outside the experiment workspace; those are read-only inputs
- write under `/hpc_stor03/sjtu_home/chaolei.liu/sure`
- write to `/hpc_stor03/sjtu_home/chaolei.liu/TTS/F5-TTS`
- use `base_model/eval_data`, `f5tts_staged`, selection, holdout, or official
  benchmark data for fine-tuning
- change F5-TTS model architecture except through `SURE_TTS_ARCH_WRAPPER`
- change tokenizer, vocab, mel config, or vocoder training
- run from-scratch training
- run unbounded epochs or training commands without the wrapper timeout
- copy `reference_audio` as `prediction_audio`
- emit empty, silent, or placeholder wav files
- reuse one generated wav for multiple different target texts
- replace SURE scoring with an internal WER number

`artifacts/candidate_changes.json` must be a JSON object containing:

```json
{
  "candidate_type": "inference",
  "idea_text": "short description of the implemented idea",
  "changed_fields": ["inference_config.nfe_step"],
  "arch_config": {},
  "training_config": {},
  "inference_config": {"nfe_step": 32},
  "defaults": {},
  "diff_from_defaults": {},
  "produced_artifacts": {"samples_jsonl": "artifacts/samples.jsonl"}
}
```

For architecture candidates, the architecture wrapper writes a compatible
change record under `models/f5tts_arch/candidate_changes.json` and
`artifacts/candidate_changes.json`; keep or extend that record rather than
omitting it.

## Baseline Inference Shape

A simple inference-only candidate should delegate synthesis to the batch
wrapper:

```bash
"$SURE_TTS_PYTHON" "$SURE_TTS_BATCH_INFER_WRAPPER" \
  --cfg-strength 1.85 \
  --speed 0.94 \
  --text-cleanup typography \
  --idea-text "Inference-only candidate with lower guidance, slightly slower speech, and typography cleanup."
```

The batch wrapper handles absolute path resolution, per-row prompt audio/text,
worker logs, resume of already valid wavs, process-group cleanup, and the SURE
artifact contract.

## Optimization Ideas

Useful directions include:

- Tune inference parameters such as `nfe_step`, `cfg_strength`,
  `sway_sampling_coef`, `speed`, cross-fade duration, and silence removal.
- Try target-text splitting or punctuation normalization before inference.
- Use workspace-local temporary config files under `working/`.
- Add conservative post-processing that improves ASR intelligibility without
  changing the spoken words.
- After inference-only is stable, try very small, bounded fine-tuning runs that
  save checkpoints under `models/` and never modify `base_model/root`.
- Try controlled architecture candidates through `SURE_TTS_ARCH_WRAPPER`, for
  example smaller/larger DiT depth, feed-forward width, text conv layers,
  `qk_norm`, attention mask, or activation checkpointing.

Keep changes small and measurable. The metric is semantic intelligibility
through SURE's TTS WER pipeline, not subjective naturalness.
