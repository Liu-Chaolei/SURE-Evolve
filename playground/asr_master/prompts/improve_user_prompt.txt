## How to implement improvement ideas

- **Hyperparameter changes**: Override train.py CLI args (e.g., `--num-encoder-layers`, `--encoder-dim`, `--learning-rate`, `--num-epochs`, `--base-lr`).
- **Architecture changes**: If modifying the model, either monkey-patch `model.py` / `zipformer.py` functions, or import and subclass model components before calling train.py.
- **Data augmentation**: Adjust SpecAugment params (e.g., `--time-mask-factor`, `--freq-mask-factor`).
- **Training schedule**: Tune learning rate, warmup-related CLI parameters, epoch count, and batch duration while preserving the recipe scheduler.
- Always preserve the overall train -> decode -> parse WER -> print `\boxed{{}}` structure.
- **CRITICAL**: Use RELATIVE paths: `./icefall_recipe`, `./icefall_data`, `./icefall_root` (NO `os.path.dirname(__file__)` needed)

- **CRITICAL**: Use a memory-aware `--max-duration` instead of a tiny fixed batch. Icefall's parser default is 200, but its own examples use larger values when memory allows. Choose the initial value from per-GPU memory, not summed memory: >=80GB -> 2200, >=48GB -> 1700, >=32GB -> 1400, >=24GB -> 1000, <24GB -> 800, and unknown memory -> 1000. Allow `ASR_MAX_DURATION` to override this. If CUDA OOM occurs, retry with a smaller value (2200 -> 1700 -> 1400 -> 1000 -> 800 -> 500 -> 300 -> 200). If a run fails with `grad_scale is too small`, `loss=inf`, `metric=nan`, or non-finite outputs/gradients, retry with `--use-fp16 0`; do not reduce `--max-duration` unless the error is OOM.
- **CRITICAL**: Do NOT patch or replace icefall's optimizer or scheduler. Zipformer training depends on the recipe's `ScaledAdam(get_parameter_groups_with_lrs(...), clipping_scale=2.0)` optimizer and `Eden` scheduler; replacing them with `AdamW`, plain `Adam`, or another scheduler can make fp32 training diverge.
- **CRITICAL**: Do not hide failures by printing placeholder scores such as `\boxed{{999.0}}` with exit code 0. If no real WER was produced, exit non-zero after printing the diagnostic output so the outer debug loop can continue.
