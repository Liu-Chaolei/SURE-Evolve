# SD Direct-24 A/B 文献消融实验（旧版）

> 本页保留 Direct-24 版本的实验设计。该部署已归档；新版 Native-MCTS 的启动与恢复说明见
> [SD 部署登记](sd_deployments.md)，研究机制见 [原生研究说明](xlab_native_research.md)。

本文记录 Direct-24 的 A/B 实验安排，供复现和撰写论文时使用。
当前只开展 A、B，C、D 已取消；公共基线是两组共享的参照，不是第三条搜索轨迹。
本文不包含实测性能结论，不代表所有实验已经完成。

## 1．实验目标

在保留跨轮实验反馈、统一执行与 SURE 评测的条件下，比较提供和不提供外部
语音文献时，系统最终找到的 SD 方案有何差异。

| 组别 | 外部文献 | 跨轮反馈 | 含义 |
|---|---|---|---|
| A：完整系统 | 有 | 有 | 利用文献、历史结果和当前最佳方案持续研究 |
| B：去文献 | 无 | 有 | 利用任务信息、模型知识和历史结果持续研究 |
| 公共基线 | 不开展方案搜索 | 不开展方案搜索 | 原始 DiariZen 配方的固定参照 |

主要比较是 A 与 B，用于分析额外提供外部文献的贡献。两组都使用同一套 SURE
评测，因此 A/B 本身不能证明统一评测的贡献，也不能验证跨轮反馈的独立贡献。

B 组仍然拥有 LLM 的预训练知识和共同的模型源码、接口说明，不能称为“无语音
知识”。本次消融对象是额外提供的外部文献及其使用要求。

## 2．规模与共同条件

| 项目 | 统一设置 |
|---|---|
| 任务与基础模型 | AMI 单通道说话人日志化；DiariZen / WavLM-Base+ |
| 搜索范围 | `search_scope: all`，允许结构、训练、推理及组合改动，无类型配额 |
| 独立搜索次数 | A、B 各一次 |
| 搜索预算 | 每组固定六轮，每轮四个候选槽位，最多 24 个候选 |
| 两组合计 | 最多 48 个候选；公共基线单独训练一次 |
| 方案生成预算 | 每轮最多八次生成尝试，接收至多四个候选 |
| 调试预算 | 每个候选最多三次调试，次数跨恢复保存 |
| 数据划分 | 固定 train、train_validation、search、selection、holdout，按会议分组 |
| 训练初始化 | 官方 WavLM-Base+ SSL 权重，其余网络按固定规则新初始化 |
| 随机种子与精度 | seed 3407、BF16 |
| 训练 batch size | 每卡 48，四卡全局 batch size 为 192，梯度累积步数为 1 |
| 训练资源与上限 | 每个训练候选四张 NPU，最多 100 epoch |
| 验证与模型导出 | 固定训练验证口径，patience 10，最佳五个 checkpoint 平均 |
| LLM 路由 | 控制器 `glm-5.3-flash`；XLab 分析、生成、评审、定稿 `gpt-6-astra` |

本方案将 batch 48 按现有 SD 配置的每卡口径定义，计数单位为训练语音 chunk。
公共基线、A 和 B 的所有训练候选统一使用 BF16、每卡 batch 48；这两项是共同
实验条件，不作为候选自由搜索的变量。训练验证与推理 batch 不随此项自动调整。

一次独立搜索指从公共初始方案和空实验历史出发，完成六轮候选生成、执行与选优。
同一条轨迹里的 24 个候选不构成 24 次独立重复。

训练候选可以继承当前最佳方案的设计和代码，但按照共同初始化规则重新训练，
不继承父候选的优化器状态或累积其训练时长。仅修改推理的候选复用本轮开始时
冻结的最佳模型。两组都不在搜索结束后追加未计入预算的复训。

相同候选机会和训练上限不意味着相同实际计算量：模型规模、推理候选比例、
早停时间及调试次数可能不同。因此必须同时报告实际成本，不能将该对照直接
描述为严格等 FLOPs 或等费用实验。

## 3．A/B 的差异如何落实

配置开关：

```yaml
# A：完整系统
sure:
  ablation:
    use_literature: true
    use_feedback: true
```

```yaml
# B：去文献
sure:
  ablation:
    use_literature: false
    use_feedback: true
```

### A 组：提供冻结文献上下文

当前实现从已验证的 SD survey 按领域相关性选取 24 条 evidence 和 16 条 references，
保存为冻结文献上下文并记录 SHA256。方案必须引用提供的证据 ID，评审检查文献支持。

本次直接检验的是这份冻结文献上下文的增量价值，不能据此推断论文库规模越大
效果越好，也不能把它描述为每轮动态检索整个论文库的对照实验。

### B 组：关闭外部文献输入

不读取 survey、论文正文、文献摘要、引用检索结果或文献缓存；候选引用列表为空，
评审中的外部文献支持要求标记为不适用。仍然检查候选的可执行性、区分度和
实现一致性，不要求 B 虚构引用来通过验证。

### 两组共同保留

- 相同的任务说明、模型源码与接口参考、训练和评分约束。
- 相同的分析、生成、评审、定稿和候选实现流程。
- 各自轨迹内的候选得分、执行状态、实际改动、研究总结与最佳方案更新。
- 相同的上下文上限、模型配置、调用重试与候选调试预算。

A/B 使用独立工作区、会话、生成缓存和历史记录，不能共享研究总结、候选结果
或最佳方案。允许共享公共基线和固定数据、软件资源。对提示词的差异仅围绕
文献可用性及引用要求展开，不给某一组额外的优化建议。

## 4．统一评测与选优

主指标为 DER，越低越好。当前冻结协议为：

- collar 为 0.25 秒，底层 `regions='all'`，计入重叠语音。
- 参考和预测按相同 manifest 的 UEM 区域裁剪，聚合使用会话平均 DER。
- 使用冻结的 SURE Eval、MeetEval `0.4.3` 和 `md-eval-22.pl`，记录版本与文件指纹。
- 各阶段保持相同评分规则，不能让候选修改归一化、计分区域或评分器。

数据的使用顺序：

1. train 与 train_validation 用于训练和训练过程中的 checkpoint 选择。
2. search 的 DER 用于六轮研究反馈与搜索排名。
3. 每组搜索结束后，取 search 前两名有效候选，与公共基线一起在 selection 上选优。
4. A、B 都选定并冻结最终方案后，再开启 holdout 评测；无需等待已取消的 C、D。
5. holdout 只用于评价冻结的最终方案与基线，不进入研究反馈，不根据其结果重新选优。

如果有效候选不足两个，使用已有候选；全部失败时回退公共基线。保留基线回退
结果，不因没有提升而重新开展一条搜索。

## 5．执行流程与失败处理

1. 核对公共配置、A/B 开关、数据指纹、LLM、镜像和源代码版本。
2. 训练并保存公共基线，校验其模型包、训练完成证据和原始评分报告。
3. 在分配给各组的运行环境回放公共基线评分，确认两组具有可比的执行与评分条件。
4. A、B 独立开展六轮研究；每组可同时提交一轮四个候选，两组共享四个执行槽位。
   第五个及之后的任务等待空闲槽位；每轮全部候选结束后才更新反馈和下一轮方案。
5. 每轮保存候选、缺额、失败、得分、父方案和实际成本；性能停滞不提前结束六轮。
6. 按统一 selection 与 holdout 流程完成最终评价，汇总表格和曲线。

生成不足四个候选时，缺额占用当轮槽位；执行失败不补抽新候选。基础设施中断
恢复原候选，不改变代码、初始化或实验预算；候选实现失败与基础设施失败分开记录。
不把失败候选的 DER 填成 0，也不混入有效候选的平均分。

## 6．资源与当前部署

遵循 `/shared/chaolei.liu/rules.md` 及 `http://127.0.0.1:18088/`。
本次授权资源池为 **10085–10088、10094–10097**；这些是 Slurm 作业编号，
不是固定节点名。10089 不在使用范围内。后续重新开展实验时需核对当时有效分配。

每个 allocation 原申请 8 张 Ascend 910B3、64 CPU、256 GiB 内存和 100 GB 临时盘。
当前执行池固定为 n04/10085 和 n05/10086，每台机器两个独占槽位，总执行并发
上限为四个候选。每个训练候选使用四卡、32 CPU、120 GiB 内存和 32 GiB 共享内存；
同一节点两个候选使用不重叠的 NPU。纯推理候选仍使用一卡，也占一个槽位。
临时缓存按候选隔离，节点整体仍受原 100 GB 临时盘配额限制。只在这两台机器
等待和执行，不自动退回普通 sbatch，不使用 10024/10029。取消 C/D 不等于取消资源作业。

正式训练通过 Slurm step 内的 `slurm-docker-run` 启动，设备映射由包装器管理。
镜像在 n01 构建并固定 digest；重要产物和检查点保存在 `/shared`。

每个候选记录：ID、组别、轮次、父方案、假设、文献引用、实际代码和参数改动、

| 公共基线 | 待填 | 待填 | — | — | — | 待填 | 待填 |
| A：完整系统 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 |
| B：去文献 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 |

计算与报告约定：

- 内部 DER 保存原始比例，展示时乘以 100；A/B 差值使用百分点。
- 相对基线误差下降为 `100 × (DER_baseline − DER_method) / DER_baseline`，
  使用同一数据划分；基线 DER 为零时不计算该比例。
- “优于基线候选数”默认指 search 上严格优于公共基线的有效候选，不混用
  “优于本轮父方案”这一不同口径。另行记录生成缺额和失败数量。
- 成本包括失败、调试与重试。公共基线训练成本单列，不在两组中重复计为训练；
  不能只用最终成功尝试的耗时代表整个搜索成本。
- 区分模型执行时长、排队时间、LLM 用量及评测成本；没有可靠价格信息时报告
  token，不推测费用。缺失的资源测量明确标注，不用零代替。

配套绘制两张 search 曲线：最优 DER 随候选槽位推进变化，以及最优 DER 随累计
加速器时数变化。记录缺额和失败，使“第几个有效候选”与“已消耗多少预算”不混淆。
最终测试结果单独呈现，不逐轮查看 holdout 绘制所谓进化曲线。

## 8．结论边界与后续工作

每组只有一次搜索，不报告跨运行均值±标准差或搜索稳定性显著性检验，也不能
把 24 个候选视作 24 个独立样本。A/B 的排名和差值属于本次固定设置下的观察。
若 A 优于 B，可表述为本次实验中外部文献上下文对应更好的最终搜索结果；
不能单凭一次结果断言其稳定优越或推广到 ASR、TTS。

若 A/B 接近或 B 更好，同样完整报告，并结合候选机制、失败率和成本分析，
不根据已见结果更换预算或重跑直到得到预期排序。后续独立重复应另行安排。

统一评测的重要性由另一份方案讨论：
[SD 评测协议回放实验](sd_evaluation_protocol_replay.md)。它可以复用 A/B 的冻结
预测产物，当前仅为后续方案，不是本次 A/B 消融的必做阶段，也不会自动启动。
