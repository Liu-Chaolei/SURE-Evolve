# SD 评测协议回放实验方案

状态：待开展。本文件仅规定后续实验，不包含实测结论，也不改变现有搜索或评测配置。

## 1．研究问题与结论边界

对同一批冻结的 SD 候选预测结果，改变评测协议后重新评分，考察候选排名、
最优候选以及相对基线的改善判断是否发生变化。

本实验旨在提供以下证据：自动研究需要明确、统一并记录评测口径，否则协议
差异可能影响候选比较与研究结论。SURE 的作用是将协议、预测产物和评分记录
连接起来，使比较可复现、可追溯。

需要区分三个结论：

- 分数发生变化，说明指标对协议敏感；仅凭这一点还不能说明选优受到影响。
- 排名或改善判断发生变化，说明协议选择可能影响研究决策。
- 本实验不证明某一种协议天然最正确，也不证明 SURE 独有的优势或性能增益。
  不同协议可能对应合理但不同的评价偏好。

本轮采用离线评分回放，不重新训练、不重新开展反馈搜索，也不把回放结果传回
正在运行的研究流程。它不等价于“不同评分反馈驱动多轮搜索”的闭环对照实验。

## 2．候选与数据

### 2.1 候选来源

候选池必须固定一个部署版本（Direct-24 或 Native-MCTS），在清单中记录 `deployment_id`，
不跨版本合并主分析。优先使用该版本的公共基线及 A、B 两组产生的全部有效候选；C、D 已取消，不是本实验
的前置条件。每个候选取其预算内最终实现对应的一份冻结输出，不把调试中间版本
作为额外候选。

默认在 A、B 搜索结束后冻结候选清单。如果提前分析，先记录统一的截止时间或
轮次，纳入截止点之前的全部有效候选；不得看过排名变化后挑选候选。

主分析分别对“基线 + A 候选”和“基线 + B 候选”进行，合并候选池作为补充。
同一搜索轨迹内的候选存在依赖，不能当作多次独立实验。对于同一分析池内
SHA256 完全相同的预测文件，主排名分析只保留一份，保存全部候选 ID 对应关系；
若与基线相同，优先保留基线。另行保留未去重结果便于核查。

### 2.2 默认数据范围

主回放使用原搜索集 `search`，所有候选必须覆盖完全相同的会议。固定以下内容：

- 参考 RTTM、会议清单、输入通道和音频版本。
- 原始 UEM 区域、参考与预测的裁剪方式、时间单位及精度。
- 候选模型、推理配置和预测 RTTM。
- 评分器、依赖及容器版本，除指定干预外的所有评分参数。

同一轮回放不混用 search、selection 与 holdout。主实验不读取 holdout，也不根据
回放结果追加 holdout 选优。若以后在 selection 上验证，另建完整的候选×协议
矩阵并单独报告，不能将两个划分的分数拼接排名。

### 2.3 每个候选需要保存的输入

| 内容 | 要求 |
|---|---|
| 候选身份 | `candidate_id`、A/B/基线、轮次、父方案及干预类型 |
| 预测产物 | 原始 `hyp.rttm`、实际参与评分的裁剪后 RTTM、各自 SHA256 |
| 覆盖证据 | `processed_sessions.json` 或等价记录，证明完成所有目标会议 |
| 评分输入 | 参考 RTTM、会议 manifest、UEM 与 SHA256 |
| 原有结果 | 原始 search DER、评分报告、pipeline ID、协议参数 |
| 复现信息 | 模型包、权重和推理配置指纹，以及运行目录 |

无发言预测的会议可以没有 RTTM 行，不能据此认定该会议未运行；用覆盖证据区分
有效的空预测和缺失推理。训练失败、推理未完成或输出损坏的候选不进入排名，
但必须记录数量和排除原因。

如果 RTTM 已被清理，只能从该候选冻结的模型包和推理配置重新生成一次共同输出，
随后各协议共享这份输出；不得为不同协议分别调整推理。缺失且无法复现的候选
如实登记，不通过补训或另一个 checkpoint 替代。

## 3．协议矩阵：每次只改变一个因素

使用 `R0`–`R3` 命名评分协议，避免与研究组 A/B/C/D 混淆。

| 协议 ID | collar | 重叠语音 | 聚合方式 | 与 R0 的唯一差异 |
|---|---:|---|---|---|
| R0：参考协议 | 0.25 秒 | 计入 | 会话平均 DER | 当前冻结的 SURE 口径 |
| R1：无 collar | 0 秒 | 计入 | 会话平均 DER | 边界容忍度 |
| R2：忽略重叠 | 0.25 秒 | 忽略 | 会话平均 DER | 重叠语音计分区域 |
| R3：总体 DER | 0.25 秒 | 计入 | 总错误说话人时长 / 总参考说话人计分时长 | 会话权重 |

可选补充 R4：collar 为 0.5 秒，其余同 R0。是否加入必须在查看候选回放结果前
决定；最小正式方案只做 R0–R3。

对于 R1、R2、R3，在实验记录中补充其实际使用依据，例如工具默认参数、任务文档
或相关论文的明确计分设置。无法找到使用依据的设置仍可作为敏感性分析，但不能
描述为已经发生的真实协议混用。

当前已有冻结记录位于：
`runs/sd_ablation_20260914_v3/metric_protocol.json`。其中包括：

- MeetEval `0.4.3`；pipeline ID 为 `sd.any.der.meeteval_v1`。
- collar `0.25`；底层 `dscore` 的区域参数为 `regions='all'`。
- 主聚合方式为 `session_mean_error_rate`。
- 参考和预测按同一 manifest 的 UEM 区域裁剪；`md-eval-22.pl` 已记录 SHA256。

以上是已记录的部署事实，执行时应校验文件与镜像是否仍与记录一致。

### 3.1 两个重要的实现细节

**重叠语音选项：**当前 MeetEval 接口使用 `regions` 参数，不能假定存在
`skip_overlap` 参数。实现 R2 前查阅固定版本实际支持的选项，通过有已知结果的
重叠样例确认其确实只排除了参考中的重叠区域。不得通过修改预测 RTTM 来“去重叠”，
也不得顺便改变说话人匹配、UEM 或 collar。

**聚合分母：**设会议 `s` 在指定协议下的漏检、误检、混淆时长分别为
`MISS_s`、`FA_s`、`CONF_s`，参考说话人计分时长为 `REF_s`：

```text
DER_s = (MISS_s + FA_s + CONF_s) / REF_s
R0    = mean_s(DER_s)
R3    = sum_s(MISS_s + FA_s + CONF_s) / sum_s(REF_s)
```

`REF_s` 必须与该协议的 collar、重叠处理和 UEM 一致；计入重叠时，它不等于会议
音频长度。R3 不能简单按音频时长加权，更不能对所有候选统一套用未经裁剪的时长。

当前 SURE 的逐会话 JSON 导出错误分量，但未导出上述分母。回放工具需要从底层
评分结果保存真实分母及其字段映射，不能通过“错误数 / 已四舍五入的 DER”反推，
也不能丢弃零错误会议。R3 直接复用 R0 的逐会话原始计数，不必再次推理或评分。

R0 必须复现原有裁剪流程。直接向评分器额外传入 UEM 可能与“先裁剪 RTTM、再评分”
存在语义差异；如果要比较两种做法，应另建实验，不能悄悄替换 R0。

## 4．统计指标与计算约定

内部保存 DER 的原始比例值，例如 `0.12`；展示时乘以 100，写为 `12.00%`。
差值使用百分点：`100 × (DER_Rp − DER_R0)`，不要与相对变化百分比混写。

排名统一使用 DER 保留 10 位小数后的值判同分，不使用表格展示时的两位百分数。
不同协议使用同一规则。

### 4.1 主指标

| 指标 | 定义与处理 |
|---|---|
| Kendall τ-b | 衡量 Rp 与 R0 的候选排序一致性，保留并列名次；全部同分时报告不可估计 |
| 最优候选集合 | `T_p = argmin DER_Rp`，并列时保留所有候选，不任意宣称唯一冠军 |
| 最优集合变化 | 报告 `T_p` 是否与 `T_0` 相同，以及是否完全没有共同最优候选 |
| 候选对排名反转率 | 在两种协议下都非并列的候选对中，严格优劣次序颠倒的比例 |
| 相对基线的判断变化 | 将每个非基线候选标记为“改善 / 持平 / 退步”，列出 R0→Rp 的转移数量 |

候选对排名反转的计算为：

```text
d0 = DER_R0(i) - DER_R0(j)
dp = DER_Rp(i) - DER_Rp(j)

有效候选对：d0 != 0 且 dp != 0
严格反转：  d0 * dp < 0
反转率：    严格反转对数 / 有效候选对数
```

同时报告总候选对数、有效对数和并列导致排除的对数；分母为零时记为不可估计。
对相对基线的判断变化，单独报告“改善↔退步”的严格翻转，不把“改善→持平”混入。

### 4.2 补充指标

- 各候选的 DER 及相对 R0 的百分点变化。
- Spearman 排名相关性，作为 Kendall τ-b 的补充。
- 最优集合发生变化的具体候选、研究假设、改动和对应误差分量。
- 各协议产生并列的比例，避免把边界容忍度增大后的同分误读成排序完全稳定。

不要将不同协议的数值混在一起组成主排名。所有候选在每一种协议下都有完整分数，
主分析比较的是“完整协议之间的排序差异”。协议混用案例如需展示，单独标注为
说明性示例，不作为本实验的主要量化证据。

### 4.3 可选的不确定性分析

如需区间，采用按会议配对 bootstrap：固定 seed 3407，重采样 1,000 次；同一次
重采样对全部候选和协议使用相同会议索引，并重新聚合 DER、排名及反转率。
会话平均和总体 DER 分别按各自公式重算，不对已聚合分数直接 bootstrap。

区间只反映“固定候选池下，会议抽样带来的波动”，不代表独立搜索的稳定性。
报告不可估计的重采样次数；不能把会议片段、候选对或同一搜索的候选当作独立重复。

## 5．执行步骤

1. **冻结实验约定。** 在看回放分数之前，确定候选截止点、数据划分、R0–R3、
   去重方式、同分规则和是否加入 R4/bootstrap，保存 `replay_plan.yaml`。
2. **汇总候选输入。** 导出全部有效候选及基线的 RTTM、覆盖证据、参考和 UEM；
   生成 `candidates.csv` 与文件指纹，登记排除原因。
3. **检查输入一致性。** 所有协议使用相同的输入文件；所有候选覆盖同一会议集；
   检查时间范围和通道。协议导致某会议参考计分时长为零时，停止检查其含义，
   不默默丢弃该会议以凑出分数。
4. **验收评分器。** 用人工可核对的小 RTTM 测试完美预测、漏检、误检、混淆、
   边界偏移、重叠和长短会议聚合；确认每个开关实际生效。
5. **先复现 R0。** 与原始 search 报告逐候选核对，原始比例值的绝对误差容限
   设为 `1e-8`。超出容限则先定位文件、版本或裁剪差异，不开始其他协议的结论分析。
   若原报告只保留展示精度，补取机器精度报告，不能伪造更高精度的一致性结论。
6. **批量回放。** 用冻结输出计算 R1/R2，保存底层逐会话计数；从 R0 原始计数
   计算 R3。所有记录绑定 candidate ID、protocol ID 和输入指纹。
7. **计算统计量。** 分别分析 A 池、B 池，再给出合并池补充结果；生成完整表格
   和图，不只展示发生反转的候选。
8. **选择解释案例。** 如存在反转，按预先约定的规则选择：优先最优候选分歧，
   其次相对基线“改善↔退步”翻转；多个案例按 candidate ID 排序取首个。
   根据真实改动和错误分量讨论原因，区分观察与机制假设。
9. **冻结报告。** 保存分析代码版本、环境、协议与全部结果；不将这些结果作为
   新的搜索反馈，也不据此修改已冻结的主实验设置。

纯回放一般只需 CPU。若需补生成预测，再使用相应模型运行环境；在本集群执行
评分容器或补推理时遵循 `/shared/chaolei.liu/rules.md` 与
`http://127.0.0.1:18088/`，重新核对当时有效的 Slurm 分配，不把旧作业号视为永久资源。

## 7．如何解释结果

**如果出现排名或改善判断反转：**可以说明评测协议会影响这批候选的相对判断，
因而自动研究闭环需要统一且可追溯的计分条件。将 SURE 对输入、协议和报告的
统一记录作为实现这一要求的机制说明。

**如果只改变分数，排名稳定：**说明绝对 DER 对协议敏感，但当前候选的选优结论
在测试范围内稳健。不要把数值偏移夸大为选优错误。

**如果所有结果都稳定：**如实报告该任务、候选池和协议范围内的稳健性；不能为
追求显著差异而追加极端协议、删掉候选或更换数据。

建议论文将本节命名为“评测协议对候选比较的影响”或“统一评测的必要性分析”。
本实验提供协议敏感性及可复现回放的证据，不单独证明 SURE 比其他正确实现同协议
的工具更优，也不把某一协议下的较低 DER 描述为模型性能提升。
